# 隐私与数据处理说明

本项目在设计和实现上遵循「凭据最小化、数据不外传」原则。请在使用前阅读本说明。

## 1. 本项目不会做的事

- **不含任何上传逻辑。** 抓取到的数据与凭据都不会被发送到除 B 站官方接口以外的任何服务器。
- **不存储登录账号的个人资料。** 不使用、不保存你的昵称、头像、UID、大会员状态等账号信息。
  登录 UID 仅在建立 WebSocket 连接时用于组装认证包（内存中，不写入任何数据文件）。
- **不把凭据写入任何数据产物。** JSONL / CSV / TXT / SQLite 中不含 SESSDATA、bili_jct、buvid 等字段。
- **不把凭据写入日志。** 所有凭据字段在落日志前统一经过掩码处理（只保留首尾各 4 字符）。

## 2. 凭据存放位置与权限

推荐使用 `bili-danmaku login` 扫码登录，凭据由程序写入本机：

| 位置 | 说明 |
|------|------|
| `.secrets/cookies.json` | 默认。已加入 `.gitignore`，不会进版本库。 |
| 环境变量 `BILI_SESSDATA` | 纯内存模式，**完全不落盘**。适合临时使用或 CI。 |

- 文件权限：POSIX 下设为 `0600`；Windows 下移除继承并仅保留当前用户访问权限。
- 一键清除：`bili-danmaku purge`（删除 `.secrets/` 下所有凭据文件）。

## 3. 请勿把凭据贴到任何对话、issue 或日志中

`SESSDATA` 等价于账号登录态，持有者可以以你的身份执行操作（包括发送弹幕、修改资料）。
本项目从设计上避免让你手抄凭据；请优先使用扫码流程。

## 4. 关于抓取到的第三方数据

本项目**只采集有用户文字内容的弹幕与 SC 正文**（含正文内嵌的表情占位符）。
进房 / 上舰 / 点赞 / 礼物 / 房间数据等事件**不落盘** ——
它们仍会被接收并计入统计的「过滤」计数，只是不写入任何文件。

弹幕数据包含**其他观众**的 UID 与昵称，属于第三方个人信息：

- 数据默认保存在本机 `data/` 目录，请自行妥善保管，不要公开分发原始数据集。
- 实测发现 B 站会对部分用户的 UID（`uid=0`）与昵称（如 `逸***`）做打码处理；
  本项目**默认原样保留**打码结果（便于统计"有多少条被平台打码"），不尝试还原。
- 提供 `--exclude-masked` 用于丢弃被打码的记录。
- 提供 `--anonymize` 用于输出脱敏数据（uid 加盐哈希、昵称掩码），便于分享样本而不泄露隐私。

## 5. 合规使用

- 仅用于个人学习、研究或自有直播间的运营分析等授权场景。
- 请遵守 B 站用户协议与相关法律法规，不要用于骚扰、人肉、批量爬取或商业转售。
- 本项目默认单房间单连接、限制并发房间数、强制 HTTP 调用最小间隔，从设计上避免给服务端造成压力。
